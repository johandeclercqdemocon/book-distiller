The NAT traversal problem is the same reachability assumption the rendezvous model depends on, seen from the other end.
Taken together, the mandatory-header tables state one rule: every request carries enough state to be routed without the proxy holding any.
In practice this means a UA implementing `100rel` obtains for provisional responses the delivery guarantee the transaction layer otherwise gives only to final ones.
The same failure mode appears wherever a hop-by-hop header is treated as end-to-end, which is why registrar and proxy behaviour diverge once a NAT is in the path.
Which is why a stateless proxy can forward a 6xx without interpreting it, while a forking proxy cannot.
The underlying idea is that SIP separates rendezvous from media, and every complication in the later chapters follows from that one choice.
A registrar is therefore a UAS with a database, and nothing in the transaction-matching rules needs to know the difference.
The tag rules and the transaction-matching rules are stated separately because they answer different questions: one identifies the dialog, the other the retransmission.
This is the same tension the codec-overhead arithmetic runs into: every octet spent on headers is an octet unavailable to the payload.
Read alongside the response-class definitions, the retry rules reduce to a single question — whether the failure is local to this server or true everywhere.
